# 보고서 대시보드 고도화 설계

- 작성일: 2026-11-13
- 대상: `kr-council-skill/assets/report.html`, `kr-council-skill/scripts/render_report.py`, `tests/test_render_report.py`
- 기준 버전: v0.3.2 (HEAD `f07be2e`)
- 상태: 사용자 승인 대기 (접근 A는 2026-11-13 승인됨, 이 문서는 아직 미승인)

## 1. 의도와 이유

위원회 보고서(HTML)는 지금 "질문 → 위원 카드 5장 → 검토 표 → 위원장 보고서" 순서로 길게 이어진다. 읽는 사람이 가장 먼저 알고 싶은 것은 위원장의 결론인데 맨 아래에 있고, 위원 5명의 판단은 같은 비중의 카드로 흩어져 있으며, 상호 검토는 표로만 나와 "누가 누구를 지지하고 비판했는지"가 한눈에 보이지 않는다.

이 변경은 보고서를 **결론 중심 대시보드**로 바꾼다. 읽는 순서를 결론 → 근거(위원 판단) → 상성(상호 검토)으로 뒤집고, 위원을 눌러 판단을 바로 볼 수 있게 한다.

사용 조건(사용자 확정):
- 공개 저장소이므로 특정 개인 환경에 의존하지 않는다.
- 혼자 브라우저로 볼 때 만족스러워야 한다.
- 보고서는 **단독 실행형 HTML 한 파일**로 공유된다(외부 폰트·CDN·이미지 파일 없음).
- 저장은 브라우저의 즉시 인쇄를 쓴다. PDF 변환 도구를 새로 만들지 않는다.

## 2. 목표 / 비목표 / 안티골

**목표**
1. 스티키 헤더: 스킬 이름, 섹션 바로가기, 다크모드 토글, 인쇄 버튼.
2. 위원장 최종 보고서를 가장 크게 보이고, 그 아래에 위원 5명의 소형 카드(이름·역할·성격 한 줄)를 둔다.
3. 소형 카드를 누르면 위원장 카드 자리로 스크롤하고, 그 카드 안에서 해당 위원의 판단을 보여 준다.
4. 카드 호버 시 그림자와 살짝 떠오르는 효과.
5. 상호 검토를 5각형 상성 지도(인라인 SVG)로 시각화한다.

**비목표**
- 점수·순위·가중치 같은 수치를 만들지 않는다. council JSON에는 점수가 없다.
- SKILL.md의 JSON 규격과 `validate` 규칙을 바꾸지 않는다. 입력 데이터는 그대로다.
- 외부 라이브러리·CDN·웹폰트를 쓰지 않는다. Python 표준 라이브러리만 쓴다.
- 보고서에서 PDF 파일을 직접 만들지 않는다.
- URL 해시 이력, 위원 판단 비교 보기 같은 추가 기능은 넣지 않는다.

**안티골(기술적으로 동작해도 실패인 경우)**
- JS가 꺼졌거나 실패했을 때 내용이 숨겨져 보이지 않는 보고서.
- "독립 전문가 5인"으로 오해하게 만드는 연출(한계 문구와 실행 방식 배너가 가려지거나 접히는 것).
- 상성 지도가 근거 없는 정량적 인상(점수처럼 보이는 굵기·숫자)을 주는 것.
- 위원 텍스트가 `<script>` 안으로 들어가는 것.

## 3. 접근 방식 비교

| 접근 | 요지 | 장점 | 단점 |
|:---:|:---|:---|:---|
| **A (채택)** | Python이 지금처럼 HTML 전체를 생성하고 위원 5명 상세를 모두 DOM에 넣는다. 바닐라 JS는 표시 전환·스크롤·테마 토글만 맡는다. 상성 지도는 서버(Python)에서 SVG로 그린다 | JS 없이도 내용이 모두 보인다. 이스케이프 경로가 한 곳. 테스트·인쇄에 유리 | 상호작용이 단순하다(전환·스크롤 위주) |
| B | council 데이터를 `<script type="application/json">`으로 심고 JS가 전부 렌더링 | 상호작용을 자유롭게 짤 수 있다 | JS 실패 시 빈 화면. 위원 텍스트가 스크립트 안으로 들어가 이스케이프 위험 증가. `advisor-card` 테스트 구조 변경 |
| C | 현재 구조에 CSS만 덧입히기 | 가장 작은 변경 | 카드 클릭 전환, 상성 지도를 만들 수 없다 |

A를 채택한 이유: 공개 저장소의 범용성(JS 없이도 읽힘), 보안 제약(위원 텍스트는 HTML 본문에서만 이스케이프), 기존 테스트 유지가 모두 맞는 유일한 방식이다. 이는 AI 판단(제 선택)이며 사용자가 승인했다.

```
│ [실행 방식 배너]  [한계 문구]            ← 항상 표시, 접히지 않음                          │
│ 제목 / 생성 시각                                                                       │
│ ── 질문 ──                                                                            │
│ ┌ 위원장 카드(가장 큼) ────────────────────────────────────────┐                        │
│ │ 파파스머프(위원장)의 최종 검토 보고서   [보고서 | 위원 판단] (JS일 때만 전환 표시)    │ │
│ │ 신뢰도·소수 의견 칩 / 동의 / 충돌 / 사각지대 / 권고 / 가장 먼저 할 한 가지          │ │

│ ── 상성 지도 ── (5각형 SVG + 범례)                                                      │
│ ── 상호 검토 표 ── (기존 표, 그대로)                                                    │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 위원장 카드와 위원 판단 전환
- 카드 안에 두 패널이 항상 DOM에 있다: 위원장 보고서 패널, 위원 5명 상세 패널(`class="advisor-card"` 5개).
- **JS가 없을 때**: 위원장 보고서 아래에 위원 5명 상세가 모두 펼쳐져 보인다. 소형 카드는 `<a href="#advisor-<id>">`라서 그 상세로 점프한다.
- **JS가 있을 때**: `<html>`에 `js` 클래스가 붙고, 전환 버튼이 나타난다. 상세는 선택된 위원 1명만 보인다. 소형 카드를 누르면 그 위원이 선택되고 위원장 카드 상단으로 스크롤한다. "위원장 보고서" 버튼으로 돌아온다. 위원장 보고서를 위원 판단으로 완전히 교체하지 않고 같은 카드 안에서 전환한다.
- 소형 카드 소개 문구(성격 한 줄)는 `references/advisors.md`의 각 위원 "관점" 문장을 줄인 것이다(5절 참조).

### 4.2 상성 지도
- 5각형의 꼭짓점에 위원 5명을 놓고, 검토 5개(`reviews`)에서 나온 **방향 간선 10개**를 그린다: 검토자 → `strongest` 위원은 **실선**(지지), 검토자 → `weakest` 위원은 **점선**(비판). 매핑(`mapping`)으로 익명 글자를 위원 id로 되돌린다.
- 서로 지지하는 쌍(A→B, B→A가 모두 strongest)은 굵게 강조한다. 굵기는 이 경우에만 달라지며, 점수를 뜻하지 않는다는 범례 문구를 붙인다.
- 색만으로 구분하지 않는다(실선/점선, 화살표 모양, 범례). 접근성: `role="img"` + `<title>`/`aria-label`로 요약 문장, 같은 정보는 바로 아래 검토 표에 이미 있다.
- 노드에 마우스를 올리거나 포커스하면 그 위원의 간선만 강조한다(JS 선택 사항, 없어도 지도는 완전하다).
- 자기 자신을 `weakest`로 고른 경우(검증이 막지 않는다)는 노드의 작은 점선 고리로 그린다. 조용히 버리거나 오류를 내지 않는다.

### 4.3 스티키 헤더와 테마·인쇄
- 헤더는 `position: sticky`. 바로가기 앵커는 `scroll-margin-top`으로 헤더에 가려지지 않게 한다. 좁은 화면에서는 바로가기가 줄바꿈되거나 가로로 흐른다.
- 테마 토큰은 `:root`에 정의하고, 다크는 `@media (prefers-color-scheme: dark)`(단 `:root[data-theme="light"]`이면 제외)와 `:root[data-theme="dark"]` 두 곳에 둔다. 토글은 `data-theme`을 바꾸고 선택을 `localStorage`에 저장한다. 읽기·쓰기는 모두 try/catch이며, 저장소를 못 써도 시스템 설정으로 올바르게 보인다.
- 테마 토글과 인쇄 버튼은 JS가 있을 때만 보인다(`.js-only`).
- **인쇄(`@media print`)**: 헤더·버튼·소형 카드 숨김, 밝은 테마 고정(저장된 다크 선택과 무관), 위원 상세 5명과 검토 표를 모두 펼침, 배너·한계 문구 표시 유지, 카드 단위로 쪽 나눔 방지. 인쇄 버튼은 `window.print()`만 호출한다.

### 4.4 호버·모션
- 소형 카드와 위원장 카드: 호버/포커스 시 `translateY(-2px)`와 그림자. `:focus-visible` 윤곽선 필수.
- `prefers-reduced-motion: reduce`이면 이동·부드러운 스크롤을 끈다.

## 5. 구현 제약 (반드시 지킬 것)

1. `tests/test_render_report.py:163`은 `class="advisor-card"`를 **정확히 5번** 센다. 상세 패널만 이 클래스를 쓰고, 소형 카드는 다른 클래스(예: `advisor-mini`)를 쓴다. `class="advisor-card x"`처럼 클래스를 덧붙이면 카운트에서 빠지므로 속성 문자열을 그대로 유지한다.
2. 이스케이프 테스트(`test_render_escapes_html`)를 유지한다. 위원 텍스트·질문·제목은 HTML 본문과 속성에서만 `_e()`로 이스케이프해 쓴다. **`<script>`는 템플릿에 고정된 정적 코드만** 들어가며, council 데이터를 JS 문자열이나 JSON으로 심지 않는다. JS는 DOM에서 `data-advisor` 같은 id만 읽는다. SVG 안의 `<text>`·`<title>`도 `_e()`를 거친다.
3. 템플릿 치환은 지금처럼 한 번의 `re.sub`로 끝낸다(값 안의 `{{...}}`가 재치환되지 않도록).
4. 템플릿에 박혀 있는 `파파스머프(위원장)`은 `render_report.py`의 상수 한 곳(예: `CHAIR_NAME`)으로 모으고 슬롯으로 주입한다. `tests/test_skill_md.py:177`이 SKILL.md의 이름 목록을 검사하므로 SKILL.md 본문은 건드리지 않는다.
5. 위원 소개 문구 출처: `references/advisors.md`의 위원별 "관점" 문장(예: 투덜이 "이 선택이 실패한다면 가장 그럴듯한 이유를 찾는다"). 문구는 렌더러의 단일 표(`ADVISOR_PROFILE` 등, id → 호칭·역할·한 줄)에서 관리하고, 기존 `ADVISOR_NAMES`는 이 표에서 파생한다. 테스트가 이 문구가 `advisors.md`에 실제로 있는 문장의 일부인지 비교해 어긋남을 잡는다. (이 표 구조는 제 결정이다.)
6. 외부 리소스 참조 금지: 렌더 결과에 `http://`·`https://` 리소스 로드(`src`, `href` 스타일시트, `@import`, `url(...)`)가 없어야 한다.
7. 한계 문구(`DISCLAIMER`)와 실행 방식 배너는 모든 상태(JS 유무, 전환 상태, 인쇄)에서 보인다.
8. `<html lang="ko">`, 한국어 기본 폰트 스택, 현재 색 토큰의 의미(`--accent` 등)는 유지한다. 새 토큰은 추가해도 된다.

## 7. 검증 (성공 판정 기준)

자동 테스트(`python -m unittest discover -s tests` 통과):
- 기존 테스트 전부 통과(카드 5개, 이스케이프, 배너, 표 등).
- 새 테스트: 렌더 결과에 `<script>`가 정적 블록 하나뿐이고 위원 텍스트(`<script>alert(1)</script>` 포함 샘플)가 그 안에 없다. 외부 URL 리소스가 없다. SVG 간선이 10개이고 서로 지지 쌍이 강조 클래스를 받는다. 자기 자신을 weakest로 고른 데이터에서도 렌더가 성공한다. `CHAIR_NAME`이 렌더에 나타난다. 소개 문구가 `advisors.md`에 있는 문장에서 왔다. 한계 문구·배너가 `hidden`/`display:none` 대상이 아니다.

브라우저 확인(Playwright, 이 환경에 설치돼 있음):
- 라이트·다크 스크린샷, 폭 375px 모바일, JS 비활성(모든 내용 보임), 인쇄 미디어 에뮬레이션(헤더 없음·밝은 테마·상세 펼침), 소형 카드 클릭 시 전환·스크롤, 콘솔 오류 0건.

위 확인 결과는 PR 본문에 실제 수행한 것만 적는다. 수행하지 못한 것은 "미검증"으로 쓴다.

## 9. 알려진 한계 / 위험
- 브라우저 인쇄는 브라우저마다 쪽 나눔이 다르다. 실제 인쇄 미리보기는 Chromium에서만 확인할 수 있다.
- 상성 지도는 한 번의 상호 검토(검토자당 지지 1·비판 1)만 보여 준다. 위원 간 관계의 일반 법칙으로 읽히지 않도록 범례에 "이 질문에서의 검토 결과"라고 쓴다.
