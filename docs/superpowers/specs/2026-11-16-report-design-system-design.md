# 보고서 디자인 시스템 적용 설계

상태: 승인 대기 (2026-11-16 작성)

## 1. 의도와 이유

위원회 최종 보고서(`assets/report.html`이 만드는 HTML 한 파일)를 공공기관 업무 문서답게 다듬는다. 사용자(전북특별자치도 공무원)는 Claude Design 캔버스에서 화면을 직접 보며 다음을 확정했다. 이 설계는 그 확정본을 생성기로 옮기는 작업이다.

- 전북특별자치도 디자인 시스템(Jeonbuk State Design System)의 색·글자·간격·모서리 규격을 적용한다.
- 화면이 너무 길어지는 문제를 탭과 하위 탭으로 해결한다(참고: elec.setynus.com의 탭+카드 배치).
- 인쇄물은 A4 세로 1장에 위원장의 최종 검토 보고서만 담는다.

기준 화면: 캔버스 artifact `https://claude.ai/artifact/XrX8Atnb74yqR1TSoBN8Sf` (2026-11-16 15:08 게시본). 이식 중 값이 헷갈리면 이 파일이 정답이다.

## 2. 목표 / 비목표 / 안티골

**목표**
- 화면: 헤더(브랜드 색)·히어로·상위 탭 4개·탭별 하위 탭·푸터 안내를 캔버스와 같게 만든다.
- 인쇄: 인쇄 아이콘을 누르면 위원장 보고서만 A4 1장에 맞춰 나온다.
- 다크 모드를 디자인 시스템의 다크 값으로 바꾼다. 상태는 색만으로 전달하지 않는다.

**비목표**
- council JSON 규격과 `validate` 규칙은 바꾸지 않는다.
- 폰트 파일을 포함하지 않는다(시스템 글꼴 폴백). 기관 상징(`emblem-basic.png`)도 넣지 않는다(원본을 구하지 못했고, 글자나 도형으로 대신 그리지 않는다).
- PDF를 직접 만들지 않는다. 인쇄는 브라우저에 맡긴다.

**안티골(기술적으로 동작해도 실패인 것)**
- JS가 꺼졌거나 실패했을 때 내용이 숨겨져 보이지 않는 보고서.
- 인쇄에서 위원 문장이 바뀌거나 요약문으로 교체되는 것(§5.3).
- 외부 폰트·CDN·URL이 들어가는 것.

## 3. 접근 방식 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A (제안)** | 기존 구조 유지. Python이 HTML 전체를 만들고 모든 내용을 DOM에 넣는다. 하위 탭·인쇄 단계는 정적 JS가 클래스만 바꿔 보이거나 숨긴다 | JS 없이도 전부 보인다. 위원 텍스트는 HTML 본문에서만 이스케이프한다. 기존 테스트 대부분 유지 | 인쇄 1장 맞춤을 JS가 맡는다(JS 없으면 맞춤 없음) |
| B | 캔버스처럼 council 데이터를 JS 상태로 두고 전부 JS가 그린다 | 캔버스와 코드가 1:1 | JS 실패 시 빈 화면. 위원 텍스트가 스크립트에 들어가 이스케이프 위험. 기존 안전 테스트 폐기 |
| C | 하위 탭 없이 CSS만(`:target`, 라디오 해킹) | JS 불필요 | 키보드·접근성 구현이 어색하고 인쇄 맞춤은 어차피 JS 필요 |

**A를 제안하는 이유**: 직전 설계(2026-11-13)의 제약(JS 없이도 읽힘, 정적 스크립트 하나, 위원 텍스트 이스케이프 한 경로)을 그대로 지키는 유일한 방식이다. 이 선택은 제(AI)의 판단이며 아직 승인 전이다.

## 4. 화면 구성 (캔버스 확정본)

- **헤더(스티키, 화면 전용)**: 브랜드 파랑 배경, 글자색은 `on-brand`. 날짜 글씨는 칩 없이 헤더 배경과 같은 색. 오른쪽에 다크 모드 스위치(role=switch)와 인쇄 아이콘 버튼(44×44).
- **히어로**: 안건 제목·질문. "실행 방식"·"한계"는 푸터로 이동(인쇄에서는 안건 카드 자체를 뺀다).
- **상위 탭**: 최종 보고서 / 위원 5명 / 상성 지도 / 상호 검토.
- **하위 탭(밑줄형, 화면 전용)**
  - 최종 보고서: 권고·"가장 먼저 할 한 가지"는 고정, 아래에 동의하는 점 / 사각지대 / 충돌하는 점.
  - 위원 5명, 상호 검토: 위원별 탭 + "전체 보기"(기본은 첫 위원). 한 명씩 볼 때 카드 폭 860px 제한.
- **위원 카드**: 이름 + "맡은 관점"(README "위원 소개" 문구) 아래 구분선, "판단 의견"은 연한 파랑+왼쪽 막대 상자, "근거" 라벨, 위험·놓치기 쉬운 점은 테두리 상자. 상호 검토 카드도 같은 규칙(가장 강한 응답=파랑 막대, 가장 큰 사각지대=빨강 막대, 모두가 놓친 것=테두리).
- **상성 지도**: 위원 이름·점을 누르면 상호 검토 탭의 해당 검토자로 이동하고 스크롤한다. JS가 없으면 기존처럼 `#advisor-<id>` 앵커로 이동한다.
- **푸터(브랜드 파랑, 화면 전용)**: 2열. 왼쪽 "보고서 안내"(실행 방식 / 한계 사항 / 출력 방식), 오른쪽 "스킬 사용 시 주의 사항"(조언 아님 / 개인 정보 / 저장 위치). 항목마다 24px 선 아이콘. 문구는 `render_report.py` 상수로 둔다(캔버스 문구 그대로).

## 5. 인쇄

### 5.1 범위와 호출
- 인쇄 아이콘 → 위원장 최종 검토 보고서만(권고, 첫 행동, 동의, 사각지대, 충돌). 안건·탭·위원·지도·검토·푸터·헤더 제외(사용자 결정).
- 방식: `<body>`에 `print-report` 클래스를 붙이고 인쇄한 뒤 뗀다. 브라우저 메뉴의 인쇄(Ctrl+P)도 같은 결과가 되도록 `beforeprint`/`afterprint`에도 연결한다(**제 판단**, §8 확인 요청).

### 5.2 A4 1장 자동 맞춤 (사용자 선택: 자동 3단계)
`beforeprint`에서 단계를 올리며 위원장 보고서 높이를 잰다(가용 높이 = 1123 − 상하 여백 114 = 1009px, 폭 794px 기준).
1. 전체 내용, 인쇄용 글자(본문 12.67px).
2. 간격·글자 축소(본문 12px = 9pt 하한 유지, 여백 8px).
3. 각 항목의 첫 문장만 + 안내문("지면 관계로 항목별 핵심만 실었습니다. 인쇄에 포함되지 않은 자세한 내용은 원본 파일을 참고하십시오.").
- 맞으면 거기서 멈춘다. 3단계도 넘치면 그대로 인쇄(꼬리 쪽은 허용하되 검사에서 경고).
- 결과를 `body[data-print-level]`로 남겨 테스트와 디버깅에 쓴다.
- 보고서가 용지보다 짧으면 위아래 중앙 정렬(`min-height:1120px`, 1123이 아닌 이유는 반올림으로 빈 쪽이 생기는 것을 막기 위함).
- 구분: 구역 상자 테두리·제목 띠·왼쪽 막대로 흑백에서도 나뉘게 한다(선 색 `#616174`).
- `@page { size: A4 portrait; margin: 0 }`와 `print-color-adjust: exact`. 인쇄는 항상 라이트 값.

### 5.3 "위원 문장은 고치지 않는다" 규칙과의 충돌 처리
CONTRIBUTING의 이 규칙 때문에 **JS가 문장을 잘라 내는 방식은 쓰지 않는다**. 제안: Python이 항목을 `<span class="s1">첫 문장</span><span class="rest"> 나머지</span>`로 나눠 내보낸다. 글자는 한 자도 바뀌지 않고 전부 DOM에 있으며, 3단계에서만 CSS가 `.rest`를 숨긴다. 문장 나눔은 `(?<=[.!?])\s` 기준이고, 나눌 곳이 없으면 통째로 `s1`이다. 샘플 데이터에서 "(1)…" 같은 번호 문장이 잘못 잘리지 않는지 테스트로 고정한다.

## 6. 구현 제약 (반드시 지킬 것)
1. 단일 HTML, 외부 URL·폰트·CDN 없음, Python 표준 라이브러리만.
2. `<script>`는 템플릿의 정적 블록 하나. council 텍스트를 JS에 심지 않는다. JS는 `data-*`·클래스만 읽고 바꾼다.
3. 모든 사용자·위원 텍스트는 `_e()`로 이스케이프한다.
4. JS가 없거나 `init`이 예외를 내면 `js` 클래스를 떼어 모든 하위 탭 내용이 보인다(기존 `test_script_falls_back_to_no_js_layout_when_init_fails` 유지).
5. 색은 디자인 시스템 토큰을 CSS 변수로만 쓴다. 굵기는 400/700. 상태색은 단어와 함께 쓴다. 호버 그림자·이동 효과는 쓰지 않는다(디자인 시스템에 정의 없음).
6. 포커스 링 2px(`--primary`, 오프셋 2px), 터치 대상 44px 이상.

토큰(라이트/다크): 배경 `#f8f8f8`/`#0f1216`, 카드 `#ffffff`/`#1c2127`, 연한 면 `#eff5ff`/`#263142`, 글자 `#1d1d1d`/`#e9ebee`, 보조 `#555555`/`#adb1b8`, 선 `#d8d8d8`/`#3c4046`, 강조 `#246beb`/`#5b96ff`, 브랜드 `#034694`/`#4072b7`, 경고 `#eb003b`/`#ff656c`. 다크의 선택된 탭은 `#4072b7` 위 `#fcfcfc`(대비 약 2.9:1이라 큰 글자 전용 — 확인 필요 항목).

## 8. 사용자에게 확인받을 것

1. **§5.3 첫 문장 분리 방식**에 동의하는가(위원 문장 보존 규칙 때문에 캔버스의 JS 자르기를 바꿨다).
2. **Ctrl+P도 위원장 보고서만 인쇄**하게 할지(제안: 그렇다. 아니면 아이콘 버튼만 해당하고 Ctrl+P는 전체 펼침).
3. **"맡은 관점" 출처**: 캔버스는 README "위원 소개" 문구를 썼다. 저장소는 `ADVISOR_PROFILE`의 한 줄 소개가 `references/advisors.md` 문장과 같아야 하는 테스트가 있다. README 문구가 advisors.md에 없으면 ① advisors.md도 같이 고친다(제안) ② 화면 상수만 따로 둔다 중 선택이 필요하다.
4. 상호 검토 카드에도 "맡은 관점"을 붙인 것(캔버스에서 사용자 요청 아님, 제 판단)을 유지할지.

## 9. 검증 (성공 판정 기준)
- `python -m unittest discover tests` 전체 통과. 새 테스트: 토큰 변수 존재, 외부 URL 0건, `@page` A4 존재, 첫 문장 분리가 원문을 보존(합치면 원문과 같음), 하위 탭이 JS 없이도 모든 내용을 DOM에 포함, 스크립트가 여전히 1개이며 council 텍스트 없음.
- 기존 테스트 중 구조에 묶인 것(`test_sections_order`, `test_chair_card_comes_before_advisor_minis`, 소형 카드 관련)은 새 구조에 맞게 고치되, 고친 이유를 PR에 적는다. 지우지 않는다.
- 실제 브라우저(Playwright): 1280/768/360px × 라이트/다크, JS 비활성, 콘솔 오류 0건.
- 인쇄 PDF: 샘플 보고서와 긴 보고서(항목 3배 길이) 모두 **1쪽**, 최종 단계 번호 기록, 흑백 변환에서도 구역 구분 가능.
- 캔버스는 인쇄 창·`@page`·쪽 번호를 검증하지 못했으므로, 인쇄 관련 판정은 저장소 구현에서만 한다.
