# 카카오톡 챗봇 호스팅: 서버리스 vs 국내 VPS

## 권고

**서버리스(관리형 서비스)를 먼저 택하세요.** 운영 경험이 적고 혼자 유지한다는 조건에서는 월 3만 원대 VPS를 직접 굴리는 것이 더 위험합니다. 다만 Firebase를 그대로 고르기보다는 아래 한 가지만 확인하고 결정하세요.

- 카카오 i 오픈빌더의 스킬 서버는 5초 안에 응답해야 하고, 외부 호출이 느리면 콜백 방식을 써야 합니다. Cloud Functions의 콜드 스타트(첫 호출 지연)가 이 제한과 부딪칠 수 있습니다. 최소 인스턴스 1개를 유지하거나, Cloud Run처럼 컨테이너 기반으로 가는 편이 안전합니다.
- 대화 기록 저장소는 Firestore나 Cloud SQL 같은 관리형 DB를 쓰고, 서울 리전(asia-northeast3)을 고르세요.

## 근거

1. **트래픽 규모.** 하루 수백 명이면 서버리스 무료 구간이나 월 수천 원~1만 원대로 충분합니다. VPS 3만 원은 대부분 놀게 되는 용량에 돈을 내는 셈입니다.
2. **운영 부담.** VPS는 OS 패치, 방화벽, SSL 갱신, 백업, 장애 대응이 모두 본인 몫입니다. 혼자 하면 이 부분이 가장 먼저 무너집니다. 서버리스는 이 대부분을 제공자가 맡습니다.
3. **개인정보 보호.** 직접 서버를 두면 접근통제, 암호화, 로그 관리 같은 안전조치 의무를 본인이 전부 구현해야 합니다. 관리형 서비스는 저장 시 암호화, IAM 기반 접근 제어, 자동 백업이 기본으로 따라옵니다. 보안 사고 확률은 대체로 "미숙한 자가 운영"보다 "관리형"이 낮습니다.

## 주요 위험

- **비용 폭주.** 서버리스는 사용량 과금이라 버그나 악성 트래픽으로 요금이 튈 수 있습니다. 예산 알림과 호출 상한을 반드시 설정하세요.
- **벤더 종속.** Firestore에 깊게 맞추면 이전이 어렵습니다. 대화 기록은 단순한 구조로 두고 내보내기(export) 경로를 확보하세요.
- **개인정보 법적 의무.** 카카오톡 사용자 식별값과 대화 내용은 개인정보에 해당할 수 있습니다. 개인정보 처리방침 고지, 수집 최소화, 보관 기간 설정과 기간 경과 후 삭제, 접근 권한 최소화가 필요합니다. 해외 리전에 저장하면 국외 이전 고지 문제가 생길 수 있으니 서울 리전을 권합니다. 구체적 의무는 규모와 수집 항목에 따라 다르므로 개인정보보호위원회 안내를 확인하세요.
- **대화 내용 민감도.** 사용자가 주민번호나 건강 정보 같은 민감 정보를 입력할 수 있습니다. 필요하지 않다면 대화 원문 전체를 저장하지 말고, 저장하더라도 요약이나 최소 필드만 남기는 설계를 고려하세요.
- **VPS를 택할 경우.** 국내 VPS가 데이터 국내 보관에는 유리하지만, 그것만으로 규정 준수가 되지는 않습니다.

## 다음에 할 일

1. 오픈빌더 스킬 서버의 응답 제한(5초, 콜백 조건)을 공식 문서로 확인합니다.
2. 서울 리전 기준으로 Cloud Run(또는 Functions 최소 인스턴스) + Firestore 조합의 월 예상 비용을 계산기로 뽑아 봅니다.
3. 저장할 데이터 항목을 목록으로 만들고, 필수가 아닌 것은 빼고, 보관 기간(예: 90일)과 자동 삭제 규칙을 정합니다.
4. 예산 알림, 접근 권한(서비스 계정 최소 권한), 개인정보 처리방침 초안을 출시 전에 갖춥니다.
5. 운영 경험이 쌓이고 트래픽이 크게 늘어 비용 구조가 역전되면 그때 VPS나 컨테이너 직접 운영을 재검토합니다.

한 줄 요약: 혼자 운영하고 개인정보까지 다뤄야 한다면 "싸고 자유로운 VPS"보다 "관리 부담이 작은 서버리스 + 서울 리전 + 데이터 최소화"가 더 안전한 출발점입니다.
