## Council: 카카오톡 챗봇 호스팅 (서버리스 vs 국내 VPS)

**Architect:** 서버리스(Firebase 등 관리형, 서울 리전)로 가고 대화 저장은 최소화한다.
혼자 운영하는 초보에게는 서버 패치·방화벽·백업 책임이 없는 쪽이 개인정보 사고 면적이 작다.

**Skeptic:** 서버리스냐 VPS냐라는 틀이 문제의 핵심이 아니다. 진짜 문제는 "혼자 운영 + 개인정보"이고, 서버리스를 쓰되 대화 저장 자체를 최소화하라.
하루 수백 명이면 월 3만 원 VPS는 과투자이고, 가장 안전한 개인정보 보호는 저장하지 않는 것이다.

**Pragmatist:** Cloud Functions 또는 Cloud Run + Firestore로 지금 바로 시작하고 코드에 집중한다.
카카오 오픈빌더 스킬 서버는 5초 응답 제한에 트래픽이 작고 간헐적이라 서버리스 무료~소액 구간에 들어간다.

**Critic:** 서버리스를 택하더라도 비용 상한(예산 알림, 최대 인스턴스 수)을 먼저 걸어라. 초보가 직접 굴리는 VPS는 대화 기록이 담긴 채 가장 먼저 뚫릴 수 있다.
과금 폭주(봇, 루프), 콜드스타트, Firestore 읽기 과금 설계 실수가 서버리스의 실제 실패 모드다.

### Verdict
- **Consensus:** 네 입장 모두 서버리스(서울 asia-northeast3 리전)를 권한다. VPS는 이 규모에서 비용 낭비이고, 1인 운영에서는 보안 운영 책임이 가장 큰 위험이다. 호스팅보다 저장 설계(최소 수집, userKey 해시, 30~90일 TTL 자동 삭제, 개인정보처리방침과 삭제 요청 경로)가 개인정보 보호에 더 중요하다는 점도 일치한다.
- **Strongest dissent:** 뚜렷한 반대 입장은 없었다. 가장 강한 이견은 서버리스 고유 위험에 관한 것으로, 콜드스타트가 5초 제한에 걸릴 수 있고 과금이 예측 불가해질 수 있으며 벤더 종속도 있다는 점이다. 최소 인스턴스 1개 유지, 예산 알림, 호출 상한, 카카오 발신 검증으로 완화하는 것이 해법이라 결론을 뒤집지는 못한다.
- **Premise check:** 그렇다. Skeptic이 "서버리스 대 VPS" 이분법 자체를 문제 삼았고, 본질은 운영 부담과 대화 저장 설계라고 재정의했다. Architect도 이를 수용한다. 또한 "국내 VPS가 법적으로 더 안전하다"는 가정은 틀렸다. 위험은 서버 위치가 아니라 암호화, 접근통제, 보관기간 설계에 있다.
- **Recommendation:** Firebase(Cloud Functions 또는 Cloud Run + Firestore)를 서울 리전에 고정해 시작한다. 배포 전에 (1) 예산 알림과 최대 인스턴스 수 설정, (2) 필요한 필드만 저장하고 카카오 userKey는 해시 처리, (3) Firestore TTL로 자동 삭제, (4) 처리방침과 수집 동의 및 삭제 요청 경로 마련, (5) 응답이 5초를 넘길 수 있으면 최소 인스턴스 1개 또는 즉답 후 콜백 구조를 적용한다. 최신 요금표, 카카오 정책, 개인정보보호법 세부는 이 의회가 직접 검증하지 않았으므로 배포 전에 확인해야 한다.
